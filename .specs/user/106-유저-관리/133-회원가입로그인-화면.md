# 회원가입/로그인 화면

## 개요
사용자가 서비스에 접근하고 개인화된 기능을 사용할 수 있도록 회원가입 및 로그인 화면을 구현한다.

## 요구사항

### 1. 회원가입 화면
- [ ] **이메일 입력**: 사용 가능한 이메일인지 확인 (형식 검증).
- [ ] **비밀번호 입력**: 보안 강도를 위한 최소 조건 확인 (예: 8자 이상).
- [ ] **비밀번호 확인**: 입력한 비밀번호가 일치하는지 확인.
- [ ] **닉네임 입력**: 서비스 내에서 표시될 이름.
- [ ] **회원가입 버튼**: 모든 필드가 유효할 때 활성화.
- [ ] **로그인 링크**: 이미 계정이 있는 사용자를 위한 로그인 화면 이동 링크.

### 2. 로그인 화면
- [ ] **이메일 입력**
- [ ] **비밀번호 입력**
- [ ] **로그인 버튼**: 계정 정보 확인 후 메인 화면으로 이동.
- [ ] **회원가입 링크**: 계정이 없는 사용자를 위한 회원가입 화면 이동 링크.

### 3. 공통/기타
- [ ] **유효성 검사 피드백**: 잘못된 입력 시 즉시 피드백 제공 (예: "이메일 형식이 올바르지 않습니다").
- [ ] **에러 처리**: 네트워크 오류 또는 서버 에러 시 사용자에게 알림.

## 기술 설계

### API 엔드포인트 (예시)
- `POST /api/auth/register`: 회원가입 요청
  - Body: `{ email, password, nickname }`
- `POST /api/auth/login`: 로그인 요청
  - Body: `{ email, password }`
  - Response: `{ accessToken, refreshToken }`

### 상태 관리
- 로그인 성공 시 발급받은 Access Token을 클라이언트(로컬 스토리지 또는 쿠키)에 저장.
- API 요청 시 Authorization 헤더에 Bearer Token 포함.
