# TheTable 제품 로드맵

> 작성일: 2026-02-10

## Phase 1: 다자간 회의 기본 수준 달성 (1-2개월, 우선순위: 높음)

### 1.1 현재 상태 분석

#### ✅ 이미 구현 완료
- **3명 에이전트 동시 회의**: Host, PM, TechLead 안정적 운영
- **안건 기반 진행**: YAML 설정, 안건 완료 감지, 상태 추적 (`pending` → `in_progress` → `completed/deferred`)
- **MCP 도구 통합**: GitHub 이슈/PR 조회, 에이전트별 도구 선택
- **스트리밍**: 실시간 응답 스트리밍 (Main LLM `streaming=True`)
- **대화 요약**: 메시지 5개 초과 시 자동 요약 (Task LLM)
- **회의 종료 감지**: Host 발언 키워드 + 안건 80% 완료 시 LLM 분석
- **무한루프 방지**: `turn_count` (최대 1000), `consecutive_host_delegations` (3회), tool-calling 루프 (50회)
- **동적 안건 관리**: LLM 기반 안건 추출/수정/삭제, 담당자/결정사항 추적

#### ⚠️ 미흡/개선 필요
- **에이전트 수 확장**: 5명 이상 에이전트로 확장 시 라우팅 복잡도, 성능 미검증
- **동적 에이전트 참여/퇴장**: 회의 중 에이전트 추가/제거 불가
- **회의록 영속화**: 회의 종료 시 상태 소멸, 저장 기능 없음
- **사용자 참여 (is_human)**: `HumanNode` 구현되었으나 CLI에서 미사용, UX 개선 필요
- **계층적 에이전트**: `AgentProfile.agents` 필드 지원하지만 실제 미사용
- **에러 복구**: LLM/MCP 도구 실패 시 재시도 로직 없음
- **성능 최적화**: 매 발언마다 멘션 추출, 안건 업데이트 LLM 호출
- **테스트 커버리지**: 통합 테스트 부족

### 1.2 "기본적인 다자간 회의" 기준 정의

#### 핵심 요구사항
1. **안정성**: 5명 이상 에이전트로 확장 시에도 안정적 운영
2. **영속성**: 회의록 저장 및 조회 기능 제공
3. **사용성**: CLI UX 개선, 사용자 발언 입력 지원
4. **복구력**: LLM/MCP 도구 실패 시 재시도 및 복구
5. **성능**: LLM 호출 빈도 최적화, 메모리 관리

### 1.3 Gap 분석 및 구현 과제

| 기능 | 현재 상태 | 목표 | Gap | 구현 과제 |
|------|-----------|------|-----|-----------|
| 에이전트 확장 | 3명 고정 | 5명 이상 | ⚠️ 성능 미검증 | 5명 에이전트 성능 테스트, `refill_speakers` 최적화, 발언 기회 균등 분배 |
| 회의록 저장 | 미구현 | JSON/Markdown/DB | ❌ 기능 없음 | 회의록 저장 API, 메타데이터 추적 (시작/종료 시간, 참여자, 안건), 검색 기능 |
| 사용자 입력 | `HumanNode` 미사용 | CLI UX 개선 | ⚠️ UX 부족 | 프롬프트 개선, 타임아웃 설정, 발언 히스토리 저장 |
| 에러 복구 | 로그만 출력 | 재시도 + fallback | ❌ 로직 없음 | Exponential backoff, 대체 모델/도구 fallback, 실패 횟수 제한 |
| LLM 호출 최적화 | 매 발언마다 호출 | 정규표현식 우선 | ⚠️ 비효율 | 멘션 추출 정규표현식화, 안건 업데이트 주기 조정 (3턴마다) |
| 통합 테스트 | 단위 테스트만 | E2E 시나리오 | ❌ 테스트 부족 | 회의 시작→진행→종료 시나리오, MCP 도구 사용 테스트 |

### 1.4 Phase 1 구현 우선순위

1. **회의록 영속화** (최우선)
   - JSON/Markdown 저장
   - 메타데이터 추적 (시작/종료 시간, 참여자, 안건, 결정사항)
   - 회의록 조회 CLI 명령어 (`--list-meetings`, `--view-meeting <id>`)

2. **에이전트 5명 확장 검증**
   - Backend, Frontend 에이전트 재활성화
   - 성능 테스트 (발언 횟수, 처리 시간)
   - `refill_speakers` 최적화

3. **에러 복구 로직**
   - LLM 호출 재시도 (exponential backoff, 최대 3회)
   - MCP 도구 재시도 (도구별 정책)
   - 대체 모델 fallback (Main LLM → Task LLM)

4. **LLM 호출 최적화**
   - 멘션 추출: 정규표현식 (`@<name>`) 우선 적용
   - 안건 업데이트: 3턴마다만 실행

5. **통합 테스트 시나리오**
   - 회의 시작 → 안건 3개 진행 → 종료
   - GitHub 이슈 조회/생성 시나리오
   - LLM 실패 복구 테스트

## Phase 2: 기능 고도화 (2-3개월, 우선순위: 높음)

### 2.1 고급 안건 관리

- **안건 우선순위**: 안건별 우선순위 설정 (`priority: high|medium|low`)
- **안건 의존성**: 선행 안건 완료 후 진행 (`depends_on: [agenda_id]`)
- **안건 투표**: 참여자 투표 기능 (찬성/반대/보류)
- **안건 템플릿**: 반복적인 안건 패턴을 템플릿화

### 2.2 회의록 자동 생성 및 저장

- **실시간 회의록 업데이트**: 발언마다 회의록 파일 갱신
- **요약 생성**: 안건별 요약, 전체 회의 요약
- **액션 아이템 추출**: LLM 기반 액션 아이템 자동 추출
- **Export 포맷**: PDF, HTML 변환 기능

### 2.3 에이전트 성능 모니터링 및 피드백 루프

- **발언 품질 평가**: LLM 기반 발언 적절성 평가
- **에이전트 기여도 분석**: 안건 해결 기여도 정량화
- **피드백 반영**: 과거 회의 데이터 기반 프롬프트 개선
- **A/B 테스트**: 다양한 프롬프트 전략 성능 비교

### 2.4 사용자 커스터마이징 강화

- **커스텀 노드 추가**: 플러그인 API 제공 (`@register_node`)
- **커스텀 라우팅 로직**: `condition_router` 대체 가능한 우선순위 기반 라우팅
- **에이전트 프롬프트 템플릿**: YAML에서 프롬프트 템플릿 수정 가능
- **워크플로우 시각화**: Mermaid 다이어그램 자동 생성

## Phase 3: 외부 확장성 및 신규 기능 (3-6개월, 우선순위: 중간)

### 3.1 다양한 MCP 서버 통합

- **Jira**: 이슈 트래킹, 스프린트 관리
- **Slack**: 채널 메시지 전송, 알림
- **Confluence**: 문서 조회/생성
- **Calendar**: 회의 일정 자동 생성
- **Linear**: 이슈 관리
- **Notion**: 회의록 자동 저장

### 3.2 웹 인터페이스 (FastAPI + WebSocket)

- **실시간 스트리밍**: WebSocket 기반 회의 진행 상황 전송
- **REST API**: 회의 시작/종료, 안건 추가/수정, 에이전트 관리
- **대시보드**: 안건 진행률, 에이전트 발언 통계, MCP 도구 사용 현황
- **회의록 조회 UI**: 과거 회의록 검색 및 조회

### 3.3 API 서버화 (REST/GraphQL)

- **RESTful API**: CRUD 작업 (회의, 안건, 에이전트)
- **GraphQL**: 복잡한 쿼리 (회의록 검색, 통계 집계)
- **WebSocket**: 실시간 이벤트 스트리밍
- **인증/권한**: OAuth2, JWT 기반 인증

### 3.4 다중 회의 세션 관리

- **병렬 회의**: 동시 실행 회의 수 제한 (예: 최대 10개)
- **세션 격리**: 회의별 독립적인 `MeetingState` 관리
- **리소스 할당**: 회의별 LLM 호출 제한 (rate limiting)
- **회의 일정 관리**: 시작 예정, 진행 중, 완료 상태 추적

### 3.5 음성 채팅 (CosyVoice 2 + Whisper V3 Turbo)

#### 기술 스택
- **TTS (Text-to-Speech)**: CosyVoice 2 (150ms 레이턴시)
- **STT (Speech-to-Text)**: Whisper V3 Turbo (OpenAI API)

#### 구현 요구사항
- **실시간 음성 스트리밍**: WebRTC 기반 브라우저 연동
- **에이전트별 음성 프로필**: 에이전트마다 고유한 음성 톤/스타일
- **음성 명령**: 사용자 발언 음성 입력
- **오디오 회의록**: 음성 파일 저장 및 재생

### 3.6 화상 채팅 (SFU 아키텍처)

#### 기술 스택
- **SFU (Selective Forwarding Unit)**: Jitsi Meet 또는 Amazon IVS
- **WebRTC**: 브라우저 기반 실시간 통신

#### 구현 요구사항
- **다자간 화상 회의**: 최대 10명 동시 화상 지원
- **에이전트 아바타**: 2D/3D 아바타로 에이전트 시각화
- **화면 공유**: 문서, 코드, 차트 공유
- **녹화 기능**: 회의 영상 녹화 및 저장

## Phase 4: 플랫폼 확장 (6-12개월, 우선순위: 낮음)

### 4.1 LangGraph v1.0 활용

#### 주요 기능
- **Durable State**: 회의 상태 자동 영속화 (DB 연동)
- **Built-in Persistence**: StateGraph 자체 체크포인트 기능
- **Human-in-the-Loop**: 공식 휴먼 개입 API

#### 적용 방안
- 현재 수동 회의록 저장 → Durable State 자동 영속화
- 커스텀 체크포인트 로직 제거 → Built-in Persistence 활용
- `HumanNode` 커스텀 구현 → LangGraph 공식 API 마이그레이션

### 4.2 MCP 생태계 확장

#### Atlassian 공식 서버
- **Jira**: 이슈 CRUD, 스프린트 관리, 워크플로우 자동화
- **Confluence**: 페이지 조회/생성, 스페이스 관리

#### Workato (Slack)
- **채널 메시지 전송**: 회의 결과 자동 공유
- **알림 설정**: 안건 완료 시 Slack 알림
- **사용자 멘션**: Slack 사용자 ID 연동

### 4.3 에이전트 프레임워크 통합

#### CrewAI 패턴 (역할 기반)
- **역할 정의**: 에이전트 역할을 CrewAI 스타일로 정의
- **작업 위임**: Supervisor 에이전트가 작업을 하위 에이전트에 위임
- **결과 통합**: 하위 에이전트 결과를 Supervisor가 종합

#### LangGraph (복잡한 상태 관리)
- **조건부 라우팅**: 안건 상태, 발언 횟수 기반 동적 라우팅
- **상태 머신**: 회의 진행 흐름을 명시적 상태 전이로 모델링

### 4.4 에이전트 통신 (A2A 프로토콜)

#### RESTful HTTP 기반 통신
- **Agent API**: 에이전트 간 메시지 전송 (POST /agent/message)
- **Discovery**: 에이전트 자동 발견 (GET /agents)
- **Health Check**: 에이전트 상태 모니터링 (GET /agent/health)

#### 분산 아키텍처
- **마이크로서비스**: 각 에이전트를 독립적인 서비스로 배포
- **메시지 큐**: RabbitMQ, Kafka 기반 비동기 통신
- **로드 밸런싱**: Nginx, HAProxy로 에이전트 부하 분산

### 4.5 SaaS화 (하이브리드 멀티테넌시)

#### 테넌트 격리
- **DB 격리**: 테넌트별 독립 DB 스키마
- **AI 리소스 격리**: 테넌트별 LLM 호출 제한 (rate limiting)
- **회의 세션 격리**: 테넌트별 독립적인 `MeetingState`

#### 모니터링 및 분석
- **테넌트별 예측 분석**: 회의 패턴, 에이전트 사용량 예측
- **실시간 병목 감지**: Prometheus + Grafana 기반 알림
- **비용 최적화**: 테넌트별 LLM 비용 추적 및 최적화 제안
