## 1. 에이전트 확장

### 1.1 추가 에이전트 활성화
- **주석 처리된 에이전트 활성화**
  - Backend, Frontend, DevOps, Designer 에이전트 재활성화 (현재 `agent_profiles.yaml`에서 주석 처리됨)
  - 5명 이상 에이전트로 확장 시 성능 검증 필요
  - 발언 기회 균등 분배 메커니즘 추가

### 1.2 계층적 에이전트 구조 (Supervisor-Worker)
- **현재 상태**: `AgentProfile.agents` 필드로 계층 구조 지원하지만 미사용
- **구현 방안**
  - TechLead → Backend/Frontend 작업 위임
  - Supervisor가 하위 에이전트 실행 결과 수집 및 종합
  - 계층별 발언 순서 제어 로직 추가
- **참조**: `architecture-analysis.md` 섹션 4.2

### 1.3 동적 에이전트 참여/퇴장
- **현재 제약**: 회의 시작 시 고정된 에이전트만 참여, 회의 중 변경 불가
- **구현 요구사항**
  - 회의 중 에이전트 추가/제거 API 제공
  - 에이전트 참여 상태 관리 (active, inactive)
  - `pending_speakers`에서 비활성 에이전트 자동 제거
  - 안건별 필수 에이전트 동적 구성

## 3. MCP 서버 확장

## 5. 다중 회의 지원

### 5.1 병렬 회의 세션
- **현재 제약**: 단일 회의만 지원, 메모리에서만 상태 관리
- **구현 방안**
  - 회의 ID 기반 세션 관리
  - 세션별 독립적인 `MeetingState` 관리

### 5.2 회의록 영속화
- **저장 포맷**: JSON (구조화 데이터), Markdown (가독성), DB (검색/집계)
- **메타데이터 추적**: 시작/종료 시간, 참여자, 안건 목록, 최종 결정사항
- **회의록 검색**: 날짜, 참여자, 안건 키워드 기반 검색
- **참조**: `architecture-analysis.md` 섹션 4.2

## 6. 테스트 강화

### 6.1 통합 테스트
- **현재 상태**: 단위 테스트 중심, 전체 워크플로우 테스트 부족

- **CI/CD 통합**: GitHub Actions에서 자동 실행
- **성능 벤치마크**: 회의 처리 시간, LLM 호출 빈도, 토큰 사용량 추적

## 8. 성능 최적화

### 8.1 LLM 호출 빈도 최적화
- **현재 문제**: 매 발언마다 멘션 추출, 안건 업데이트 LLM 호출
- **개선 방안**
  - 멘션 추출: 정규표현식 우선 적용, LLM fallback
  - 안건 업데이트: N턴마다만 실행 (예: 3턴마다)
  - LLM 응답 캐싱: 동일 메시지 세트에 대한 응답 재사용
- **참조**: `architecture-analysis.md` 섹션 3.2

### 8.2 메모리 관리
- **현재 문제**: 대화 기록을 `MeetingState.messages`에 모두 저장
- **개선 방안**
  - 요약 후 오래된 메시지 제거 (현재는 요약만 생성)
  - 메시지 압축: 중요도 낮은 메시지 필터링
  - 메시지 아카이빙: DB 또는 파일로 이동

### 8.3 에러 복구 및 재시도
- **LLM 실패 복구**
  - Exponential backoff 재시도
  - 대체 모델로 fallback (Main LLM 실패 시 Task LLM 사용)
- **MCP 도구 실패 복구**
  - 도구별 재시도 정책 설정
  - 도구 실패 횟수 제한
  - 대체 전략 (예: GitHub API 실패 시 캐시 사용)
- **참조**: `architecture-analysis.md` 섹션 3.2, 4.2
