# 안건(Agenda) 설정

이 튜토리얼에서는 `agendas.yaml` 파일을 작성하여 회의의 안건 흐름을 설정하고, 안건별 필수 발언자를 지정하여 구조화된 회의를 진행합니다.

## 사전 준비

- [프로젝트 워크스페이스](project-workspace.md) 튜토리얼을 완료했거나, `doorae init` + `doorae project create`를 실행한 상태
- `.env`에 API key가 설정된 상태

## 1단계: agendas.yaml 구조 이해하기

`agendas.yaml`은 `agendas` 키 아래에 안건 목록을 배열로 정의합니다. 각 안건은 다음 필드를 가집니다:

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `title` | `str` | O | 안건 제목 (UI에 표시됨) |
| `description` | `str` | O | 안건 상세 설명 (에이전트 prompt에 포함) |
| `required_speakers` | `list[str]` | X | 이 안건에서 반드시 발언해야 하는 에이전트 이름 |

안건은 배열 순서대로 진행됩니다. 첫 번째 안건이 완료되면 자동으로 다음 안건으로 넘어갑니다.

## 2단계: 안건 파일 작성하기

프로젝트의 `config/agendas.yaml` 파일을 편집합니다. 기본 scaffold를 사용했다면 `.doorae/projects/<프로젝트명>/config/agendas.yaml` 경로에 있습니다.

3개의 안건으로 구성된 주간 회의를 설정해 보겠습니다:

```yaml
agendas:
  - title: "주간 현황 공유"
    description: "이번 주 진행된 작업과 주요 이슈를 공유합니다"
    required_speakers: ["Host", "PM"]
  - title: "기술 이슈 논의"
    description: "당면한 기술적 문제를 논의하고 해결 방안을 모색합니다"
    required_speakers: ["TechLead"]
  - title: "다음 주 계획"
    description: "다음 주 작업 우선순위와 일정을 확정합니다"
    required_speakers: ["PM", "TechLead"]
```

## 3단계: 회의 실행 및 안건 진행 확인하기

```bash
uv run doorae run --project <프로젝트명>
```

회의가 시작되면 안건 진행 상태 패널이 표시됩니다:

```
┌──────────────── 📋 안건 진행 상태 ────────────────┐
│  🔄 1. 주간 현황 공유 (Host) [0:45] ← 현재        │
│  ⏳ 2. 기술 이슈 논의 (TechLead)                   │
│  ⏳ 3. 다음 주 계획 (PM)                           │
└───────────────────────────────────────────────────┘
```

각 상태 아이콘의 의미는 다음과 같습니다:

| 아이콘 | 상태 | 설명 |
|--------|------|------|
| 🔄 | `in_progress` | 현재 논의 중인 안건 |
| ⏳ | `pending` | 아직 시작되지 않은 안건 |
| ✅ | `completed` | 논의가 완료된 안건 |

## 4단계: 안건 진행 흐름 관찰하기

회의가 진행되면서 다음과 같은 흐름을 확인할 수 있습니다:

1. **첫 번째 안건 시작**: Host가 "주간 현황 공유" 안건을 소개합니다.
2. **필수 발언자 참여**: `required_speakers`에 지정된 Host와 PM이 반드시 발언합니다.
3. **안건 전환**: 첫 번째 안건의 논의가 충분히 이루어지면, Host가 다음 안건으로 전환합니다.
4. **진행 상태 업데이트**: 패널이 갱신되어 완료된 안건과 현재 안건을 보여줍니다.

```
┌──────────────── 📋 안건 진행 상태 ────────────────┐
│  ✅ 1. 주간 현황 공유 (Host) [3:12]                │
│  🔄 2. 기술 이슈 논의 (TechLead) [1:05] ← 현재    │
│  ⏳ 3. 다음 주 계획 (PM)                           │
└───────────────────────────────────────────────────┘
```

## 5단계: 회의 종료 후 요약 확인하기

모든 안건이 완료되면 Host가 회의를 마무리하고, 최종 요약이 출력됩니다:

```
┌─────────── 회의 요약 ───────────┐
│ 항목              │ 값          │
├───────────────────┼─────────────┤
│ 완료된 안건       │ 3/3         │
│ Host 발언 횟수    │ 5           │
│ PM 발언 횟수      │ 4           │
│ TechLead 발언 횟수│ 3           │
└───────────────────┴─────────────┘
```

## required_speakers 활용 팁

- **안건당 1~3명**을 권장합니다. 너무 많으면 안건 진행이 길어집니다.
- `required_speakers`에 포함되지 않은 에이전트도 다른 에이전트가 `@Name`으로 호출하면 발언할 수 있습니다.
- `required_speakers`의 **첫 번째 이름**이 안건 진행 상태 패널에서 안건 소유자로 표시됩니다.
- `required_speakers`를 생략하면 Host가 자유롭게 발언자를 선택합니다.
