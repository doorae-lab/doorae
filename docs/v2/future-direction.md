# 앞으로의 계획

> TheTable이 앞으로 어떻게 발전할지 알아봐요.

---

## 8가지 확장 영역

TheTable은 앞으로 **8개 영역**에서 발전할 계획이에요.

1. 에이전트 확장
2. 사람 참여 강화
3. 새 도구 연결
4. 웹 인터페이스
5. 여러 회의 동시 진행
6. 테스트 강화
7. 모니터링 개선
8. 성능 최적화

> 💡 **쉽게 말하면...**
> 지금은 기본 기능만 있지만, 앞으로 더 많은 참여자, 더 다양한 도구, 더 편한 사용법이 추가될 거예요.

---

## 1. 에이전트 확장

### 지금 상태

**현재**
- 3명 고정: Host, PM, TechLead
- 회의 시작 전에 정해져요
- 회의 중 변경 불가능

**제약**
- 더 많은 참여자가 필요할 때 추가 어려워요
- 역할이 고정되어 있어요

### 앞으로 가능한 것

**더 많은 참여자**
- 5명, 10명까지 확장
- Backend, Frontend, Designer, DevOps 추가
- 발언 기회를 공평하게 분배

**참여자 동적 관리**
- 회의 중에 참여자 추가/제거
- 특정 안건에만 참여
- 필요할 때 전문가 초대

**계층적 구조**
- TechLead → Backend/Frontend에게 작업 위임
- Supervisor가 하위 팀을 관리
- 결과를 모아서 종합

> 🤔 **이해했나요?**
> Q: 계층적 구조가 뭔가요?
> A: 팀장이 팀원들에게 일을 나눠주고, 팀원들이 각자 일한 결과를 다시 팀장이 모으는 구조예요.

---

## 2. 사람 참여 강화

### 지금 상태

**현재**
- 사람이 직접 참여하는 기능은 있어요
- 하지만 실제로는 잘 안 써요
- 사용 방법이 명확하지 않아요

**제약**
- 언제 발언해야 하는지 모호해요
- 계속 기다려야 해서 불편해요

### 앞으로 가능한 것

**발언 입력 개선**
- "지금 발언하세요" 메시지를 명확히
- 일정 시간 지나면 자동으로 넘어가기
- 발언 히스토리 저장

**실시간 의사결정**
- 안건별 투표 기능 (찬성/반대/보류)
- 회의 우선순위 실시간 조정
- 특정 안건 건너뛰기
- 회의 일시 중지/재개

**알림 시스템**
- 중요한 결정이 나오면 알림
- 내가 언급되면 알림
- 회의 종료되면 알림

> 💡 **쉽게 말하면...**
> 지금은 AI들끼리만 회의하는데, 앞으로는 사람이 중간에 끼어들어서 의견을 말하거나 투표할 수 있어요.

---

## 3. 새 도구 연결

### 지금 상태

**현재**
- GitHub만 지원
- 이슈와 PR 관리 가능

**제약**
- 다른 서비스는 못 써요
- 확장이 필요해요

### 앞으로 가능한 것

**이슈 추적 도구**
- **Jira**: 이슈 관리, 스프린트 계획
- **Linear**: 빠른 이슈 처리

**협업 도구**
- **Slack**: 메시지 전송, 알림 받기
- **Confluence**: 문서 읽기/쓰기
- **Notion**: 회의록 자동 저장

**일정 관리**
- **Google Calendar**: 다음 회의 일정 잡기
- **Outlook Calendar**: 일정 확인

**도구 사용 개선**
- 참여자별로 필요한 도구만 선택
- 도구 실패 시 자동 재시도
- 도구 사용 통계 확인

> 🤔 **이해했나요?**
> Q: Slack 도구를 추가하면 뭐가 좋아요?
> A: 회의 결과를 자동으로 Slack 채널에 공유할 수 있어요. 팀 전체가 바로 확인할 수 있죠.

---

## 4. 웹 인터페이스

### 지금 상태

**현재**
- 명령줄(CLI)로만 실행
- 텍스트만 보여요
- 불편해요

**제약**
- 화면이 보기 어려워요
- 회의록을 찾기 힘들어요
- 통계를 볼 수 없어요

### 앞으로 가능한 것

**실시간 스트리밍**
- 웹 브라우저에서 회의 보기
- 발언이 실시간으로 나타나요
- 깔끔한 화면

**회의 관리 화면**
- 회의 시작/종료 버튼
- 안건 추가/수정
- 참여자 관리
- 과거 회의록 검색

**대시보드**
- 안건 진행률 그래프
- 참여자 발언 통계
- 도구 사용 현황
- 회의 시간 분석

**회의록 보기**
- 예쁘게 정리된 회의록
- 날짜별로 검색
- 키워드로 찾기
- PDF로 저장

> 💡 **쉽게 말하면...**
> 지금은 검은 화면에 글자만 나오는데, 앞으로는 예쁜 웹사이트에서 회의를 보고 관리할 수 있어요.

---

## 5. 여러 회의 동시 진행

### 지금 상태

**현재**
- 한 번에 회의 1개만
- 메모리에서만 관리
- 회의 끝나면 모든 내용 사라짐

**제약**
- 여러 팀이 동시에 못 써요
- 회의록이 저장 안 돼요

### 앞으로 가능한 것

**병렬 회의**
- 여러 회의를 동시에 진행
- 회의마다 독립적인 공간
- 최대 10개까지 동시 가능

**회의록 저장**
- JSON 형식: 컴퓨터가 읽기 좋음
- Markdown 형식: 사람이 읽기 좋음
- DB 저장: 검색하기 좋음

**저장되는 정보**
- 시작/종료 시간
- 참여자 목록
- 모든 발언 내용
- 안건별 결정사항
- 누가 뭐라고 말했는지

**회의 검색**
- 날짜로 찾기
- 참여자 이름으로 찾기
- 안건 키워드로 찾기
- 결정사항으로 찾기

> 🤔 **이해했나요?**
> Q: 병렬 회의가 왜 필요한가요?
> A: 여러 팀이나 프로젝트가 있을 때, 각각 동시에 회의할 수 있어요. 서로 방해하지 않아요.

---

## 6. 테스트 강화

### 지금 상태

**현재**
- 기본 테스트만 있어요
- 전체 흐름 테스트는 부족해요

**제약**
- 문제가 생겼을 때 늦게 발견돼요
- 새 기능 추가할 때 걱정돼요

### 앞으로 가능한 것

**전체 흐름 테스트**
- 회의 시작 → 진행 → 종료 전체
- GitHub 도구 사용 시나리오
- 에러 발생 시 복구 테스트
- 안전장치 작동 확인

**자동 테스트**
- 코드 변경할 때마다 자동 실행
- GitHub에서 자동으로 확인
- 문제 있으면 바로 알림

**성능 측정**
- 회의 처리 시간
- AI 호출 빈도
- 비용 계산
- 메모리 사용량

> 💡 **쉽게 말하면...**
> 테스트를 많이 하면 버그가 줄어들어요. 새 기능을 추가해도 기존 기능이 안 망가져요.

---

## 7. 모니터링 개선

### 지금 상태

**현재**
- 기본 로그만 있어요
- LangSmith로 AI 호출 추적

**제약**
- 문제를 찾기 어려워요
- 성능을 파악하기 힘들어요

### 앞으로 가능한 것

**추가 측정 항목**
- 각 단계별 소요 시간
- 안건별 처리 시간과 발언 횟수
- 도구 성공률과 응답 시간
- 메모리 사용량 변화

**대시보드**
- Grafana로 실시간 그래프
- 문제 발생 시 자동 알림
- AI 실패율 증가 감지
- 회의 시간 초과 경고

**로그 분석**
- 모든 로그를 한 곳에 모아요
- 키워드로 검색
- 문제 발생 시점 추적
- 패턴 분석

> 🤔 **이해했나요?**
> Q: 모니터링이 왜 중요한가요?
> A: 회의 중에 문제가 생기면 바로 알아차릴 수 있어요. 나중에 원인을 찾기도 쉬워져요.

---

## 8. 성능 최적화

### 지금 상태

**현재**
- 매 발언마다 AI를 여러 번 호출해요
- 모든 메시지를 계속 저장해요

**제약**
- 시간이 오래 걸려요
- 비용이 많이 들어요

### 앞으로 가능한 것

**AI 호출 줄이기**
- 멘션 찾기: 정규표현식으로 먼저 확인
- 안건 업데이트: 3번마다만 확인
- 응답 캐싱: 같은 질문은 답변 재사용

**메모리 관리**
- 요약 후 오래된 메시지 삭제
- 중요하지 않은 메시지 필터링
- DB나 파일로 옮겨서 보관

**에러 복구**
- AI 실패 시 자동 재시도 (3번까지)
- 다른 AI 모델로 대체
- 도구 실패 시 재시도 정책
- 캐시된 데이터 사용

**속도 개선**
- 병렬 처리: 동시에 여러 작업
- 우선순위 처리: 중요한 것 먼저
- 비동기 실행: 기다리지 않고 진행

> 💡 **쉽게 말하면...**
> 불필요한 AI 호출을 줄이고, 메모리를 효율적으로 쓰고, 에러가 나도 자동으로 복구하면 빠르고 안정적이에요.

## 우선순위

### 🔥 높음 (빨리 필요함)

1. **회의록 저장**: 회의 내용이 사라지지 않게
2. **에러 복구**: AI나 도구 실패 시 자동 재시도
3. **성능 최적화**: 비용 절약과 속도 개선

### 📌 중간 (나중에 추가)

4. **새 도구 연결**: Jira, Slack 등
5. **웹 인터페이스**: 브라우저에서 사용
6. **여러 회의**: 동시에 여러 팀 회의

### 💡 낮음 (미래 계획)

7. **사람 참여 강화**: 투표, 실시간 참여
8. **테스트 강화**: 자동 테스트 확대
9. **모니터링 개선**: 대시보드 추가

## 타임라인

- 회의록 저장
- 에러 복구
- 성능 최적화

### Phase 2 (2-3개월)
- 참여자 5명 이상 확장
- 사용자 참여 개선

### Phase 3 (3-6개월)
- 새 도구 추가
- 웹 인터페이스
- 여러 회의 동시 진행

### Phase 4 (6-12개월)
- 고급 기능
- SaaS 서비스화
- 음성/화상 채팅
