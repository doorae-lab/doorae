    첫 번째 회의¶

    이 튜토리얼에서는 Doorae 회의가 시작부터 끝까지 어떻게 진행되는지, 화면에 표시되는 요소들이 무엇을 의미하는지 자세히 설명합니다.

    사전 준비

    빠른 시작을 완료하여 .env 설정과 프로젝트 생성이 끝난 상태에서 진행하세요.

    회의 인터페이스 모드¶

    Doorae는 두 가지 인터페이스 모드를 제공합니다.

    모드 실행 방법 특징
    TUI (기본값) uv run doorae run --project demo 리치 터미널 UI, 사이드바, 실시간 상태 표시
    Classic CLI uv run doorae run --project demo --classic 순차적 텍스트 스트리밍, 파이프 연결 가능

    TUI 자동 전환

    터미널이 80x24 미만이거나 TTY가 아닌 환경에서는 자동으로 Classic CLI 모드로 전환됩니다.

    TUI 모드 화면 구성¶

    TUI 모드를 실행하면 터미널 전체에 리치 인터페이스가 표시됩니다.

    ┌─ Doorae ────────────────────────────────────────────────────────────────┐
│                                                                         │
│  ┌─ 대화 영역 (메인 패널) ──────────────┐ ┌─ 📋 안건 진행 상태 ─────┐  │
│  │                                       │ │  🔄 1. 프로젝트 로드맵   │  │
│  │  [Host]                               │ │     논의 (Host) [2:15]  │  │
│  │  안녕하세요, 여러분. 오늘 회의를      │ │     ← 현재              │  │
│  │  시작하겠습니다...                    │ │  ⏳ 2. 프로젝트 달성     │  │
│  │                                       │ │     계획 (Host)         │  │
│  │  [PM]                                 │ │  ⏳ 3. 스프린트 리뷰     │  │
│  │  현재 프로젝트 현황을 공유하겠        │ │     (PM)                │  │
│  │  습니다. GitHub 이슈 기준으로...      │ │  ⏳ 4. 스프린트 계획     │  │
│  │                                       │ │     (PM)                │  │
│  │  [TechLead]                           │ ├─ 참여자 ───────────────┤  │
│  │  기술적인 관점에서 말씀드리면...      │ │  🗣️ TechLead (tech_lead) │  │
│  │                                       │ │     [발언 중]           │  │
│  │    ↳ Backend (위임)                   │ │  ⚪ Host (host)          │  │
│  │    API 설계 측면에서 보면...          │ │     [대기 중]           │  │
│  │                                       │ │  ⚪ PM (project_manager) │  │
│  │                                       │ │     [대기 중]           │  │
│  └───────────────────────────────────────┘ └─────────────────────────┘  │
│  ┌─ 하단 바 ───────────────────────────────────────────────────────┐    │
│  │  Ctrl+Q 종료 | Ctrl+D 위임 토글 | ? 도움말                     │    │
│  └─────────────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────────┘

    대화 영역 (메인 패널)¶

    화면 왼쪽의 대부분을 차지하는 영역으로, 에이전트들의 대화가 실시간으로 스트리밍됩니다.

    • 발언자 이름: [Host], [PM], [TechLead] 등 각 에이전트의 이름이 고유 색상으로 표시됩니다.
    • 위임 발언: TechLead가 Backend나 Frontend에게 작업을 위임하면 ↳ Backend (위임) 형태로 들여쓰기되어 표시됩니다.
    • @멘션 하이라이트: 에이전트가 @PM, @TechLead 등으로 다른 에이전트를 호출하면 강조 표시됩니다.
    • 도구 호출 인디케이터: 에이전트가 MCP 도구(예: GitHub)를 호출하면 스피너 애니메이션이 표시됩니다.

    안건 패널 (오른쪽 사이드바 상단)¶

    현재 회의의 안건 진행 상태를 실시간으로 보여줍니다.

    아이콘 의미
    ⏳ 예정 -- 아직 논의되지 않은 안건
    🔄 진행 중 -- 현재 논의 중인 안건 (경과 시간 표시)
    ✅ 완료 -- 논의가 완료된 안건 (소요 시간 표시)
    ⏸️ 보류 -- 보류된 안건

    ← 현재 표시가 있는 안건이 현재 논의 중인 안건입니다. 각 안건 옆에는 담당 발언자 이름이 괄호 안에 표시됩니다.

    참여자 패널 (오른쪽 사이드바 하단)¶

    회의 참여자 목록과 현재 상태를 보여줍니다.

    아이콘 상태 설명
    ⚪ 대기 중 현재 발언 순서가 아닌 참여자
    🗣️ 발언 중 현재 발언하고 있는 참여자
    🔧 도구 호출 중 MCP 도구를 사용 중인 참여자
    ⌨️ 입력 대기 사람 참여자의 입력을 기다리는 중

    계층 구조가 있는 에이전트(예: TechLead 아래의 Backend, Frontend)는 트리 형태로 표시됩니다.

    키보드 단축키¶

    단축키 동작
    ++ctrl+q++ 회의 종료
    ++ctrl+d++ 위임 에이전트 발언 표시/숨김 토글
    ++question++ 도움말
    ++page-up++ / ++page-down++ 대화 스크롤

    Classic CLI 모드¶

    TUI를 사용하지 않으려면 --classic 플래그를 추가합니다.

    uv run doorae run --project demo --classic

    Classic CLI 모드에서는 안건 패널이 텍스트 박스로 표시되고, 에이전트의 발언이 순차적으로 스트리밍됩니다.

    ┌──────────────── 📋 안건 진행 상태 ────────────────┐
│  🔄 1. 프로젝트 로드맵 논의 (Host) [0:32] ← 현재   │
│  ⏳ 2. 프로젝트 달성 계획 (Host)                    │
│  ⏳ 3. 스프린트 리뷰 (PM)                          │
│  ⏳ 4. 스프린트 계획 (PM)                          │
└───────────────────────────────────────────────────┘

[Host]
안녕하세요, 여러분. 오늘 회의를 시작하겠습니다.
첫 번째 안건은 프로젝트 로드맵 논의입니다.
@PM 현재 프로젝트 현황을 공유해 주시겠습니까?
───────────────────────────────────────────────────
다음 발언 예정: PM, TechLead

[PM]
네, 현재 프로젝트 현황을 공유드리겠습니다.
GitHub 이슈 기준으로 현재 상태는...
───────────────────────────────────────────────────

    Classic CLI 모드의 특징:

    • 발언자 이름이 고유 색상으로 표시됩니다.
    • 각 발언 후 구분선(───)이 표시됩니다.
    • 위임 발언은 들여쓰기와 (위임) 표시로 구분됩니다.
    • 다음 발언 예정자 목록이 표시됩니다.
    • --hide-delegated 옵션으로 위임 발언을 숨길 수 있습니다.

    회의 진행 흐름¶

    회의는 아래 순서로 자동 진행됩니다.

    1. 회의 시작¶

    [Host]
안녕하세요, 여러분. 오늘 회의를 시작하겠습니다.
첫 번째 안건은 "프로젝트 로드맵 논의"입니다...

    Host 에이전트가 회의를 시작하고 첫 번째 안건을 소개합니다. 안건 패널에서 첫 번째 안건이 🔄 (진행 중) 상태로 변경됩니다.

    2. 안건 논의¶

    ┌──────────────── 📋 안건 진행 상태 ────────────────┐
│  🔄 1. 프로젝트 로드맵 논의 (Host) [3:42] ← 현재   │
│  ⏳ 2. 프로젝트 달성 계획 (Host)                    │
│  ...                                               │
└───────────────────────────────────────────────────┘

[PM]
GitHub 이슈를 확인해 보겠습니다...

[TechLead]
기술적인 관점에서 로드맵에 반영해야 할 사항은...
  ↳ Backend (위임)
  API 측면에서는 현재 구조를 유지하되...

    각 안건에 지정된 required_speakers(필수 발언자)가 모두 발언할 때까지 논의가 계속됩니다. Task LLM이 대화를 분석하여 안건 완료 여부를 자동으로 판단합니다.

    에이전트는 @멘션을 통해 다른 에이전트를 호출할 수 있으며, TechLead와 같은 상위 에이전트는 Backend, Frontend 등 하위 에이전트에게 작업을 위임할 수 있습니다.

    3. 안건 완료 및 전환¶

    ┌──────────────── 📋 안건 진행 상태 ────────────────┐
│  ✅ 1. 프로젝트 로드맵 논의 (Host) [5:23]          │
│  🔄 2. 프로젝트 달성 계획 (Host) [0:12] ← 현재     │
│  ⏳ 3. 스프린트 리뷰 (PM)                          │
│  ...                                               │
└───────────────────────────────────────────────────┘

[Host]
프로젝트 로드맵 논의가 마무리되었습니다.
다음 안건으로 넘어가겠습니다. 프로젝트 달성 계획에 대해...

    안건이 완료되면 ✅로 표시되고 소요 시간이 기록됩니다. Host가 다음 안건으로 자연스럽게 전환합니다.

    4. 회의 종료¶

    모든 안건이 완료되면 Host가 회의를 마무리합니다.

    [Host]
모든 안건의 논의가 완료되었습니다.
오늘 논의된 내용을 정리하면...
(액션 아이템 정리)
이상으로 회의를 마치겠습니다.

    회의가 종료되면 요약 테이블이 표시됩니다.

            회의 요약
┌──────────────────┬─────┐
│ 항목             │ 값  │
├──────────────────┼─────┤
│ 완료된 안건      │ 4/4 │
│ Host 발언 횟수   │ 12  │
│ PM 발언 횟수     │ 8   │
│ TechLead 발언 횟수│ 6  │
└──────────────────┴─────┘

    기본 에이전트 구성¶

    demo 프로젝트의 기본 에이전트 구성은 다음과 같습니다.

    agents:
  - name: Host        # 회의 진행자
    role: host
    # 회의 시작, 안건 관리, 토론 중재, 회의 마무리

  - name: PM          # 프로젝트 매니저
    role: project_manager
    mcp_tools:
      - github        # GitHub 도구 사용 가능
    # 프로젝트 일정, 이슈 상태 관리, 진행 상황 보고

  - name: TechLead    # 기술 리더
    role: tech_lead
    mcp_tools:
      - github
    agents:            # 하위 에이전트
      - name: Backend
        role: backend_engineer
      - name: Frontend
        role: frontend_engineer
    # 기술 의사결정, 아키텍처 설계, 하위 에이전트에 위임

    기본 안건 구성¶

    agendas:
  - title: "프로젝트 로드맵 논의"
    required_speakers: ["Host", "PM", "TechLead"]

  - title: "프로젝트 달성 계획"
    required_speakers: ["Host", "PM"]

  - title: "스프린트 리뷰"
    required_speakers: ["PM", "TechLead"]

  - title: "스프린트 계획"
    required_speakers: ["PM", "TechLead"]

    required_speakers에 지정된 에이전트가 해당 안건에서 반드시 발언하며, 이를 통해 모든 관련자의 의견이 반영됩니다.
