# 미팅 데이터 영속화 (Meeting Data Persistence)

> **Status**: Draft
> **Priority**: High (Phase 1)
> **Assignee**: Backend

## 1. 개요 (Overview)

현재 메모리(`MeetingState`) 상에서만 관리되는 회의 상태와 대화 내역을 영구 저장소(Persistence Layer)에 저장하여, 시스템 재시작 후에도 데이터를 유지하고 과거 회의 기록을 조회할 수 있도록 한다.

### 1-1. 배경 (Background)
- 현재는 서버 재시작 시 진행 중이던 회의 정보와 대화 내역이 모두 소실됨.
- Phase 1 로드맵에 "회의록 저장 및 조회" 기능이 명시되어 있었으나 미구현 상태.
- 단일 인스턴스 환경에서의 빠른 배포와 관리를 위해 **Embedded Database (SQLite)** 방식을 채택 (Option B).

## 2. 요구사항 (Requirements)

### 2-1. 기능 요구사항
1.  **자동 저장**:
    - 회의 상태 변경(`pending` -> `in_progress` -> `completed`) 시 즉시 저장.
    - 새로운 메시지(사용자 발언, 에이전트 발언) 발생 시 실시간 저장.
2.  **복구 (Recovery)**:
    - 서버 재시작 시, 중단된 회의(`in_progress`)가 있다면 마지막 상태를 로드하여 재개 가능해야 함.
3.  **조회 (Query)**:
    - 종료된 회의(`completed`)의 전체 대화 내역 및 요약 정보를 조회할 수 있어야 함.

### 2-2. 비기능 요구사항
- **데이터 무결성**: 파일 락(Lock) 처리를 통해 동시 쓰기 시 데이터 깨짐 방지 (SQLite 기본 기능 활용).
- **성능**: 메시지 저장으로 인한 대화 지연(Latency) 최소화 (비동기 쓰기 권장).

## 3. 데이터 설계 (Schema Design)

**Database Engine**: SQLite 3 (`data/doorae.db`)

### 3-1. Tables

#### `meetings`
회의(Meeting)의 기본 정보 및 현재 상태를 저장.

| Column | Type | Description |
|---|---|---|
| `id` | TEXT (PK) | UUID, 회의 고유 ID |
| `title` | TEXT | 회의 주제 |
| `status` | TEXT | `pending` / `in_progress` / `completed` 등 |
| `host_id` | TEXT | 방장 사용자 ID |
| `created_at` | DATETIME | 생성 일시 |
| `updated_at` | DATETIME | 마지막 상태 변경 일시 |
| `metadata` | JSON | 기타 설정 또는 확장 데이터 |

#### `agendas`
회의 안건 목록.

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER (PK) | Auto Increment |
| `meeting_id` | TEXT (FK) | `meetings.id` 참조 |
| `title` | TEXT | 안건 내용 |
| `status` | TEXT | `pending` / `in_progress` / `completed` |
| `order_index` | INTEGER | 안건 순서 |
| `discussion_result` | TEXT | 논의 결과/요약 (Updated upon completion) |

#### `messages`
대화 내역 (로그).

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER (PK) | Auto Increment |
| `meeting_id` | TEXT (FK) | `meetings.id` 참조 |
| `sender_type` | TEXT | `user` / `agent` / `system` |
| `sender_name` | TEXT | 발언자 이름 (또는 ID) |
| `content` | TEXT | 발언 내용 |
| `timestamp` | DATETIME | 발언 일시 |

## 4. 구현 상세 (Implementation Details)

### 4-1. 기술 스택
- **ORM**: `SQLAlchemy` (Async 지원 버전) 또는 `Tortoise ORM`
- **Migration**: `Alembic` (스키마 변경 관리)

### 4-2. 인터페이스 (Repository Pattern)
현재 메모리 `dict`로 관리되는 상태 저장소를 추상화하여 DB로 전환.

```python
class MeetingRepository:
    async def save_meeting(self, meeting: MeetingState) -> None:
        ...
    async def get_meeting(self, meeting_id: str) -> MeetingState:
        ...
    async def add_message(self, meeting_id: str, message: Message) -> None:
        ...
```

## 5. 마일스톤 (Milestone)
1. **Infra Setup**: SQLite DB 연결 설정, 테이블 생성 (Migration 스크립트).
2. **Repository Impl**: `MeetingRepository` 구현 및 기존 메모리 저장소 대체.
3. **Recovery Logic**: 서버 시작 시 `in_progress` 회의 로드 로직 추가.
4. **Test**: 회의 도중 강제 종료 후 재시작 시 상태 복구 테스트.
