# 안건 상태 실시간 표시 기능 설계

**날짜**: 2026-02-02
**관련 이슈**: #38
**작성자**: Claude (brainstorming session)

## 개요

회의 진행 중 안건 상태를 실시간으로 표시하여 전체 진행 상황을 한눈에 파악할 수 있도록 개선합니다.

### 목표
- 안건 상태 변경 시 자동으로 패널 업데이트
- 진행 시간 표시 (진행 중 + 완료된 안건)
- 결정사항 표시
- 현재 안건 명확히 표시

## 현재 문제

- 안건 변경 시에만 `📋 안건 1: 제목` 형태로 출력
- 전체 안건 진행 상황을 한눈에 볼 수 없음
- 출력이 스크롤되어 화면 밖으로 사라짐

## 설계 결정사항

### 1. 업데이트 방식
- **선택**: 이벤트 기반 업데이트
- **이유**: 현재 `astream_events()`가 이미 이벤트 기반, 리소스 효율적

### 2. 레이아웃
- **선택**: 단순 출력 방식 (Rich Live 미사용)
- **이유**: 구현 단순, 스크롤 히스토리 유지, YAGNI 원칙
- **향후**: Rich Live를 사용한 진짜 "고정" 패널은 별도 이슈로 진행 (#TBD)

### 3. 상태 변경 감지
- **선택**: `current_agenda_idx`와 각 안건의 `status` 비교
- **시점**: `on_chain_start` 이벤트의 `process_response` 노드

### 4. 표시 정보
- **기본**: 번호, 제목, owner, 상태 이모지
- **시간**: 진행 중 안건 경과 시간 + 완료된 안건 총 소요 시간
- **결정사항**: `decision` 필드가 있으면 표시
- **owner**: `required_speakers`의 첫 번째 (향후 개선 예정 #TBD)

### 5. 상태별 이모지
- ⏳ `pending` - 대기
- 🔄 `in_progress` - 진행 중
- ✅ `completed` - 완료
- ⏸️ `deferred` - 보류

## 아키텍처

### 주요 컴포넌트

#### 1. `format_agenda_panel()` 함수
```python
def format_agenda_panel(
    agendas: List[dict],
    current_idx: int,
    start_time: float
) -> Panel
```

**책임**:
- 안건 리스트를 Rich Panel로 포맷팅
- 상태별 이모지 선택
- 시간 계산 (진행 중 / 완료)
- 결정사항 포함 여부 판단

**입력**:
- `agendas`: 안건 리스트 (dict 형태)
- `current_idx`: 현재 안건 인덱스
- `start_time`: 회의 시작 시간 (Unix timestamp)

**출력**:
- Rich Panel 객체

#### 2. 상태 추적 로직

**변수**:
- `prev_agenda_state`: 이전 상태 튜플 `(current_idx, ((title, status), ...))`

**프로세스**:
1. `on_chain_start` 이벤트 수신
2. `process_response` 노드에서 상태 추출
3. 현재 상태 튜플 생성
4. 이전 상태와 비교
5. 변경되었으면 패널 출력

#### 3. 시간 계산 로직

**진행 중 안건** (`in_progress`):
```python
elapsed = time.time() - agenda["start_time"]
mins, secs = divmod(int(elapsed), 60)
time_str = f" [{mins}m {secs}s]"
```

**완료된 안건** (`completed`):
```python
elapsed = agenda["end_time"] - agenda["start_time"]
mins, secs = divmod(int(elapsed), 60)
time_str = f" [{mins}m {secs}s]"
```

**전제 조건**:
- 안건 상태가 `in_progress`로 변경될 때 `start_time` 설정 필요
- 안건 상태가 `completed`로 변경될 때 `end_time` 설정 필요
- 워크플로우 내부에서 처리되어야 함

## 테스트 전략

### 1. 기본 동작 확인
```bash
uv run thetable --stream -m "회의를 시작합니다"
```
- [ ] 안건 패널이 상태 변경 시 출력되는지 확인
- [ ] 진행 시간이 올바르게 표시되는지 확인
- [ ] owner가 첫 번째 required_speaker로 표시되는지 확인

### 2. 안건 전환 확인
- [ ] pending → in_progress 전환 시 패널 업데이트
- [ ] in_progress → completed 전환 시 패널 업데이트
- [ ] "← 현재" 표시가 올바르게 이동하는지 확인
- [ ] 완료된 안건의 총 소요 시간이 표시되는지 확인

### 3. 중복 출력 방지
- [ ] 같은 안건 내에서 여러 발언이 있을 때 패널이 중복 출력되지 않는지 확인
- [ ] 토큰 스트리밍 중에는 패널이 출력되지 않는지 확인

### 4. 결정사항 표시
- [ ] decision 필드가 있을 때 하위에 표시되는지 확인
- [ ] decision이 없을 때는 표시되지 않는지 확인

## 리스크 및 제약사항

### 리스크
1. **시간 필드 미설정**: 워크플로우에서 `start_time`, `end_time`을 설정하지 않으면 시간 표시 불가
   - **완화**: 기본값 사용 (회의 시작 시간)

2. **상태 변경 누락**: 워크플로우가 상태를 변경하지 않으면 패널 업데이트 안 됨
   - **완화**: 로깅 추가하여 디버깅 용이하게

### 제약사항
1. Rich Live 미사용으로 인한 "진짜 고정" 불가
   - 별도 이슈로 향후 개선
2. 스크롤 시 안건 패널이 반복 출력되어 화면이 길어질 수 있음
   - 실사용 테스트 후 필요시 개선
